# ICR Project Documentation

## Model organization

- Employee models live under `Employee::` with explicit `class_name` on associations; serializers mirror the namespace. Nested Decent Exposure controllers need `model: Employee::...`.
- Client care-domain models live under `Client::` (`SupportContact`, `Allergy`, `Diagnosis`, `LifeDetail`, `Enrollment`) with `self.table_name` and explicit `class_name` on `Client` associations. Nested `Clients::*` Decent Exposure needs `model: Client::...` or it resolves the un-namespaced constant.

## Stabilizing decisions

- Audit: paper_trail `versions` is the single audit store. Keep behavior gates on the model (`finalized_at`, `approved_at`, plus `created_at`/`updated_at`). Actor and audit-only actions live only on versions (`whodunnit`, custom `event`) - do not add `*_by` or audit-only `*_at` columns.
- Concern config used in instance methods (e.g. sortable fields) must use `class_attribute`. Module-level ivars set in `included` are class ivars and are invisible in instance methods.
- Singleton settings share one update endpoint across Inertia pages; use `redirect_back_or_to settings_path` so success and validation errors return to the originating page.
- Frontend: named exports only except Inertia page modules (those MUST default-export). Optional named `Page` (e.g. `export const Page = withLayout(Inner, "layout")`) for the resolver.

## Domain lore

### Permissions and caseloads

- Job-title "Grant all listed actions" expands to every catalogued resource action; it is not user `:admin`.
- Catalog resources used as Rolify targets need `resourcify` on the model (e.g. `ClientsManager`); without it, `SyncPermissions` fails with "Resource type Doesn't exist".
- Title-scoped gates: add the action to `PermissionsCatalog`, grant it in `db/seeds/02_required_permissions.rb`, and check via `standard_auth` / `job_title_allows?`. Do not hardcode job title names in policies.
- Facilitator roster: join `Employee.actively_employed` through `Employee#active_employees_job_title` (uses `1.second.from_now`). Do not use `Employee::JobTitle#active_employees` for same-day assignments - that association compares `starts_at` to `Date.current` (midnight) and drops rows that started later the same day.

### Calendar

- Recurring events expand-on-read on the models (`Calendar::Event#occurrences_in` / `.schedule_occurrences_in`, engine `Calendar::Recurring::ExpandOccurrences`). The calendar frontend maps serialized occurrence rows; it does not expand recurrence in JS.
- Recurring edit scopes: `edit_scope` all|future|one. All shifts the master by `(form_starts_at - occurrence_starts_at)`; future truncates and continues; just-this detaches.
- Gotcha: popover closes on click-outside. Date/time pickers inside the popover must not use a portal.
- Client schedule: mutations must invalidate the React Query schedule query or the UI shows stale/duplicate events.
- Participantable `calendar_events` is has_many through `event_participants`; use a distinct scope so the API returns each event once.
- Gotcha: a Calendar::Event relation that joins and also includes employee job_title can raise Postgres "column reference starts_at is ambiguous". Filter via a subquery of ids, then apply includes on the outer relation (no joins on the outer query).

### Payroll and timesheets

- Approve / Unapprove / bulk approve stay available until the period is finalized (`can_approve = !finalized?`). Payroll due date and `approval_window_open` are urgency signals only; they must never hard-block approval.
- Two view families per period: clients-first (`/payroll/periods/:slug/clients`) for facilitator caseload review; employee-combined (`/payroll/periods/:slug` plus employee review) for Director final approve, finalize, and export. Public period param is start-date `slug` (`YYYY-MM-DD`). Facilitators without Timesheet `index` are redirected from the employee-combined period show to the clients board.
- Facilitator review, shift-mode IHSS, and service type are per occurrence (`shift_occurrence_approvals` / `shift_occurrence_overrides` keyed by `shift_id` + `occurrence_starts_at`), kept in sync by `Calendar::Recurring` mutation services (just-this = cancel exception + detach; edit-all remaps after commit so event time-change invalidate does not wipe the remap). Director final approval is timesheet-level (`timesheets.approved_at`). Finalize and export never wait on facilitator stamps.
- `PayPeriod.for_period_dates` finds by start calendar day and returns that row unchanged, or creates with the requested start/end and start-date `slug`. Settings decide dates only at create; existing `starts_at`/`ends_at`/`slug` never rewrite, and neighbors are never reshaped. GET show does not create periods; index may create the current window.
- Recurring payroll surface: `PayPeriod#shift_occurrences` (via `Shift#occurrences_in`) for hours, review tables, and counts. Occurrence row `id` matches hours OT keys; mutations use `shift_id` (the real Shift UUID).
- Hours truth lives in `Payroll::Hours::Engine` (collect with workweek lookback -> IHSS consumption ledger -> policy classifier -> in-period report). `EmployeePeriodHours` delegates to it. OT workweek is `Setting.overtime_workweek_start`, not `payroll_period_day`.
- OT/DT are labeled per shift-day and reported by the workday date, so a shift crossing a pay period boundary splits its premiums between periods. IHSS consumption is windowed per pay period (`Payroll::Hours::PeriodWindow`): lookback pieces consume the prior period's assignments, and `ClientPeriodIhssHours` clips to the same window. Exemption criteria are evaluated on the whole shift before any clipping or IHSS slicing.
- Employee `overtime_policy`: `standard` (Wage Order 15 daily/weekly/DT/7th-day via settings) or `personal_attendant` (Wage Order 15 / LAB 1454 daily/weekly via settings, no DT/7th-day). Criteria overtime exemptions are straight-time regular, not unpaid.
- IHSS classification runs first via `Payroll::IhssHourClassifier` with stable client-id order and per-client consumption tags. When `Setting.ihss_co_employer` is false, only company hours feed OT math; when true, all hours feed OT. `ClientPeriodIhssHours` reads the same consumption ledger.
- Attaching a shift or changing event times/participants clears timesheet `approved_at` and occurrence approval rows for that shift.
- Semi-monthly with "last day of month": first period 1st-14th, second 15th-last day. Monthly with last day: last day of prior month through second-to-last day of current month.
- OT exemption criteria field is still named `category` and matches `service_type.slug`.

### Compliance, time off, dashboard

- Compliance template revision column is `form_version` - do not name it `version` (PaperTrail owns that association). Flipper key `compliance_forms` defaults off; no Sidebar or Spotlight entry. Incomplete drafts use `incomplete` scope (draft only); the queue uses `open_statuses` (draft + submitted).
- Time off: accrual and balances stay with Paychex; this app does not earn or enforce banks.
- Dashboard: when `user` is nil, `Dashboard::Stats` uses `Client.none` / `Employee.none` / `Calendar::Event.none` / `Timesheet.none` instead of Pundit. Nested rows are Structs; use `Payload#to_h` for plain hashes. `Dashboard::StatsSerializer` subclasses `BaseSerializer` (not `ApplicationSerializer`).

## Frontend and test footguns

- Monetized fields serialize via `ApplicationSerializer.currency_for` as `Money` (`amount` / `cents` / `currency_iso`). Do not string-format Money in serializers. `flattenToPaths` keeps Money as a leaf so CurrencyInput can read it from form initial data.
- Button labels use Title Case (capitalize every word), e.g. Approve All.
- Mantine date/time inputs expect strings; shared inputs accept Date or string and normalize to ISO string before passing in.
- Linaria class order: when a view-specific class must override a base class, use a combined selector like `&.${event} { ... }` so it wins regardless of CSS emission order.
- Page chrome: `theme.other.page.maxWidth` is the shared content width. Default panel fill is `pageChrome.panelFill` / `panelSurface`; outer shells that nest panels use `wrapper` / `panelWrapperSurface`. `panelSurface` sets `--icr-field-bg` / `--icr-field-border`. Do not invent per-page panel backgrounds.
- Form submit-with callback: when set, default submit is skipped and the normal destination is optional.
- Serializer smoke: Identification uses the `id_type` column; serializers must use `:id_type`, not `:type`.
- TipTap Menu components (BubbleMenu, FloatingMenu) must be imported from the `/menus` subpath, not the main package.
- Lib specs that register at-exit blocks with doubles: stub the class's `at_exit` so real at-exit is not registered.
